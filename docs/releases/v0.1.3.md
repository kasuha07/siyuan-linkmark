## 更新内容

### 缓存管理与持久化规模化

- **缓存权威化与分页查询**（ADR 0015、0018）：前端不再维护完整缓存镜像，只保留当前作用域的工作集；缓存匹配、修订标记、游标分页全部由 kernel 缓存权威负责。面对万级条目缓存，前端内存与 DOM 工作量只随活动视图增长，不再随缓存总量增长。
- **checkpoint + journal 追加式持久化**（ADR 0019）：缓存索引不再整文件重写，每次持久化批次只追加一条修订标记的日志记录，索引压实（compaction）时合并为新检查点。实测万级条目批量刷新从约 25 GiB 磁盘写入降至每批一次写入。
- **变更事件携带变更键**（ADR 0018）：无关缓存变更不再触发全量工作集同步。
- **缓存操作返回变更回执**：显式缓存操作（固定、清除等）返回精确的变更回执（mutation receipts），调用方无需猜测哪些条目发生了变化。

### 前端架构与渲染性能

- **插件类拆分**（ADR 0014）：`index.ts` 从 1,599 行拆分为子系统模块——前端缓存客户端、设置面板、缓存管理对话框、图标选择器对话框、链接发现、变更发现、观察器注册表、渲染调度等；模块间通过构造函数注入依赖，消除运行时循环引用。
- **观察器生命周期由 Protyle 事件接管**（ADR 0013）：变更发现精确限定于内容容器，避免应用级 DOM 变更噪声。
- **规则离开路径优化**：单次 cssRules 快照索引，消除 O(D×R) 的删除复杂度。
- 交互式链接发现路径简化，消除无操作规则映射拷贝。

### 修复

- **修复图标无法缓存的问题**：base64url 编解码在 goja 内核环境失效，导致解析得到的图标无法落盘、刷新后丢失。
- 修复 kernel 重载后工作集刷新死循环，统一游标接受语义。
- 修复批量刷新基线失效：删除先于任务创建发生时，条目不再复活。
- 修复缓存过期清理与固定（expire/pin）之间的 TOCTOU 竞态。
- 清除生成的图标后，旧配置的 monogram 不再落地。
- 修复飞书路由类型图标被公共目标安全校验误丢弃的问题。
- 修复解析失败通知与过期清理的未处理拒绝。
- 缓存权威初始化失败时显式应答 unavailable，并统一各入口的计数口径。
