# Generate icon rules only for present scopes

Status: superseded by ADR 0012

Linkmark generates Icon rules only for Present scopes instead of every fresh cache entry, because at the targeted thousand-to-ten-thousand entry scale a stylesheet covering the whole cache reaches multiple megabytes and its attribute-prefix selectors cost O(visible links × cached scopes) on every style recalc. The existing DOM discovery already collects the scopes present in mounted editors and static containers to drive fetching, so the scan becomes the sole rule builder: full scans rebuild the rule set from their results, evicting scopes that left the DOM, and local scans only add rules; because local scans never evict, a link removal or an href/data-href rewrite escalates to a full scan through the render-work debounce, so the rule set stays bounded by current document content rather than accumulating historical edits. The accepted cost is a first-frame pop-in for cached scopes on fresh window load, mitigated by running the initial scan immediately instead of on the debounce timer, and escalated full scans over the same document query the initial scan already performs, coalesced per edit burst. Per-element styling via CSS custom properties was rejected because it writes inline styles to editable SiYuan document nodes, which the project convention forbids, and because protyle re-creates elements during editing. Per-region add/remove diffs were rejected as an eviction mechanism because protyle re-creates elements during editing, so region identity is unstable, and because evicting a scope correctly requires knowing it left the whole document, which only a full scan can establish.
