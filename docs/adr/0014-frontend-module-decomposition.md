# Decompose the plugin class into frontend subsystem modules

ADR 0015 supersedes the complete local Cache-view ownership described here;
the module boundary and dependency-direction decision remain in force.

Linkmark's plugin class grew to 1,599 lines as the render pipeline, cache operations, and dialog UIs accumulated in one `index.ts`. The frontend is now split by subsystem, matching the existing `frontend-*` module convention: `FrontendCacheClient` owns the local cache view, the Cache revision/epoch baseline, Kernel RPC calls, and fetch orchestration; `SettingsPanel`, `CacheManagerDialog`, and `IconPickerDialog` own their UI; small pure modules host shared DOM and label helpers. The plugin class remains the composition root for lifecycle, Protyle observation, and render-work scheduling, because scan, binding, and scheduling interleave with all subsystems and were deliberately left for a separate decision. Extracted classes never import the plugin class: dependencies arrive through constructor injection (kernel RPC, shared settings object, `t()`) and narrow callbacks (`onCacheChanged`, `onEntryCountChange`, `onManualRefreshFailed`, action bags), which avoids runtime circular imports. Rejected alternatives were a mixin-style file split (would shrink files without introducing real state ownership) and passing the plugin reference into every dialog (would couple UIs to the composition root). The refactor is behavior-preserving and covered by the existing typecheck, lint, and vitest gates.
