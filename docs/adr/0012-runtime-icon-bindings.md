# Bind present links through transient DOM markers

Status: accepted

Linkmark may attach a transient `data-linkmark-key` marker to Present link elements and map those markers to icons with one shared layout rule plus one short rule per Present Icon binding key. This is the only permitted editable-node rendering attribute and is not precedent for additional DOM metadata. The marker contains a short opaque Runtime binding token, while the in-memory binding map retains the final scope key selected after icon precedence is resolved. A route link governed by a Pinned domain icon therefore resolves to the domain binding, but exposes only its instance-local token; tokens increase monotonically, are never reused within a plugin instance, and reset on unload. This keeps selectors short, avoids embedding or escaping URLs, and prevents stale markers from matching later bindings. This replaces URL attribute-prefix selector expansion and whole-stylesheet text publication while preserving the invariant that Linkmark never persists rendering metadata into document content: inline `style` and `custom-*` attributes remain forbidden because SiYuan converts them to span IAL, while the ordinary `data-linkmark-*` marker is disposable frontend state that Lute does not retain. Local discovery may add or update bindings, but Full discovery remains the authority that removes departed bindings; Linkmark does not maintain a MutationObserver-driven element index or scope reference count. Cache changes are synchronized according to their effect: an unchanged binding updates its CSSOM rule directly, while Pinned or shared-scope precedence changes, snapshot replacement, revision gaps, and epoch changes request Full discovery. Each synchronous publication inserts or updates destination CSSOM rules before changing element markers, then removes departed rules only after their markers are gone. The shared layout rule does not generate `content`; each binding rule does, so a stale or temporarily unmatched marker remains invisible instead of reserving an empty icon slot. An in-memory binding map is the publication authority. Normal updates mutate individual CSSOM rules; if CSSOM access or mutation fails, Linkmark rebuilds the compact stylesheet from that map and reacquires rule references instead of restoring URL selector expansion. If compact reconstruction also fails, Linkmark removes all markers and the damaged stylesheet, retains the desired binding state without stale rule references, logs the failure once, and retries only on the next natural Full discovery or cache change. Full discovery removes markers that no longer apply and reclaims their rules. Disabling icons or unloading the plugin removes all Linkmark markers from the current DOM before removing the stylesheet and clearing the binding map. Removed SiYuan nodes require no tracking, and interrupted cleanup remains fail-invisible until the next Full discovery. The accepted cost is rebinding elements that SiYuan re-creates and explicitly removing markers when their bindings cease to apply.
